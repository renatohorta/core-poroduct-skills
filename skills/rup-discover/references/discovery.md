# Discovery document

Seven sections, each a `## <Name>` heading. Fill each only with what the user confirmed.

- **Problem** — who suffers what, today, and what it costs them. One short paragraph, no solution in it.
- **Users** — the kinds of people who use or are affected by it, what each wants to get done, and who decides.
- **Goals** — the outcomes that make this worth doing, each observable (how would we notice it worked?).
- **Non-goals** — things that are reasonable but deliberately out of scope for now, with the reason.
- **Anti-goals** — things this must never do or become, even if they would help a goal (for example never lock users in, never store card data).
- **Constraints** — fixed limits: deadline, budget, team, technology, regulation, existing systems to fit.
- **Open questions** — what is still unknown or disputed, who can answer, and what depends on the answer.

Tips: ask for a concrete recent example before asking for abstractions; when an answer is vague ("fast", "easy"), ask what number or behavior would count; keep the user's own words.
