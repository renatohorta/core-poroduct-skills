# Django on Windows with Hermes — Pitfalls & Workarounds

## Hermes venv contaminates sys.path

The Hermes agent's own venv (`C:\Users\<user>\AppData\Local\hermes\hermes-agent\venv`) leaks into `sys.path` when running Django management commands or pytest. This causes `lxml` / `pptx` / other C-extension import errors because the Hermes venv has different (older) versions.

### Fix: `_clean_manage.py`

Create a wrapper at the project root that strips Hermes paths before importing Django:

```python
#!/usr/bin/env python
import os
import sys

def main():
    os.environ.setdefault("DJANGO_SETTINGS_MODULE", "config.settings")
    sys.path = [p for p in sys.path if "hermes" not in p.lower()]
    os.environ["PATH"] = os.pathsep.join([
        p for p in os.environ.get("PATH", "").split(os.pathsep)
        if "hermes" not in p.lower()
    ])
    from django.core.management import execute_from_command_line
    execute_from_command_line(sys.argv)

if __name__ == "__main__":
    main()
```

Usage: `python _clean_manage.py <command>` instead of `python manage.py <command>`.

### Fix: `_run_tests.py` (pytest)

Same pattern but for pytest:

```python
#!/usr/bin/env python
import sys, os
sys.path = [p for p in sys.path if "hermes" not in p.lower()]
os.environ["PATH"] = os.pathsep.join([
    p for p in os.environ.get("PATH", "").split(os.pathsep)
    if "hermes" not in p.lower()
])
import pytest
sys.exit(pytest.main(sys.argv[1:]))
```

Usage: `python _run_tests.py tests/accounts/ -v --create-db`

### Fix: `tests/conftest.py`

For pytest, a conftest.py at `tests/conftest.py` also works:

```python
import sys, os
sys.path = [p for p in sys.path if "hermes" not in p.lower()]
os.environ["PATH"] = os.pathsep.join([
    p for p in os.environ.get("PATH", "").split(os.pathsep)
    if "hermes" not in p.lower()
])
```

## Git on Windows — SSH key path

The `terminal` tool runs bash (git-bash/MSYS), not cmd.exe. SSH key paths must use MSYS-style forward slashes:

```bash
# $HOME em git-bash ja resolve para /c/Users/<usuario>
GIT_SSH_COMMAND="ssh -i $HOME/.ssh/id_ed25519 -o StrictHostKeyChecking=accept-new"
```

## Force-push to overwrite bot commits

When an external bot (Lovable/gpt-engineer-app, etc.) pushes commits that overwrite your working tree changes:

1. Restore your files from a known-good commit: `git show <good-commit>:path/to/file > path/to/file`
2. Commit your changes locally
3. Force push: `git push --force <remote> <branch>`

The `--force` flag is necessary because the remote is ahead of your local branch with the bot's commits.

## TanStack Router — routeTree.gen.ts

This file is auto-generated by TanStack Router whenever you create/rename/delete route files. It should be:

1. Added to `.gitignore`: `src/routeTree.gen.ts`
2. Removed from git tracking: `git rm --cached src/routeTree.gen.ts`

The file is regenerated automatically by the dev server (`vite dev`) or can be manually regenerated with the TanStack Router CLI.
